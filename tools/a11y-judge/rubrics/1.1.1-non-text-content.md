# Rubric — SC 1.1.1 Non-text Content (Level A)

> Provenance: authored 2026-07-13 from the W3C *Understanding SC 1.1.1* document
> (WCAG 2.1). VPAT/auditor findings were quarantined from authorship.

## 1. Normative text

> **1.1.1 Non-text Content** — All non-text content that is presented to the user
> has a text alternative that serves the equivalent purpose, except for the
> situations listed below.
> - **Controls, Input:** If non-text content is a control or accepts user input,
>   then it has a name that describes its purpose. (See also SC 4.1.2.)
> - **Time-based Media:** … a text alternative at least identifies the non-text content.
> - **Test:** … at least a descriptive identification.
> - **Sensory:** … at least a descriptive identification.
> - **CAPTCHA:** text alternative identifies and describes the purpose; alternative
>   forms for different disabilities are provided.
> - **Decoration, Formatting, Invisible:** implemented so it can be ignored by AT.
>
> **Level A.**

### Scope of THIS judge

axe already checks **presence** of `alt`/accessible names (F65, F38/F39, `image-alt`).
This rubric evaluates the part axe cannot: **whether a text alternative that IS
present serves the *equivalent purpose*** given the surrounding context — i.e.
alt-text QUALITY and adequacy. Missing-alt cases are axe's job; if the probe shows
a genuinely missing name on an informative image, note it but treat the primary
question as adequacy.

## 2. What the evidence looks like

- **`nameRoleValue` / accessible-name dump** — per image (`<img>`, `role="img"`,
  inline `<svg>`, CSS-background surrogates when captured): `tag`, `role`, computed
  `accessibleName`, and its source (alt / aria-label / aria-labelledby / title /
  figcaption). Empty names are flagged.
- **`readingOrder` text context** — up to ~200 characters of surrounding
  DOM-order text (caption, adjacent paragraph, link text, table cell). This is the
  material you compare the alt text *against*.
- **Image crop screenshot** — the rendered pixels. You must actually look: rate
  whether the alt conveys what a sighted user gets from the image in this context.

Read the accName **relative to** the context text. The question is never "is the
alt string plausible in isolation" but "does it deliver the equivalent information
*that this image contributes here*, without redundantly repeating adjacent text."

## 3. Decision procedure (walk in order)

1. **Classify the image's role in context** from crop + surrounding text:
   (a) informative/semantic, (b) functional (link/button graphic), (c) complex
   (chart/diagram/data), (d) decorative/redundant, (e) image of text.
2. **Decorative (d):** PASS if it is correctly hidden (empty `alt=""`, or
   `role="presentation"`/`aria-hidden`, no name). If a purely decorative image
   carries a verbose/junk name that adds screen-reader noise → severity 1–2 finding,
   usually still `pass` unless the noise is misleading.
3. **Functional (b):** the name must describe the **destination/action**, not the
   picture. "search" not "magnifying glass". Wrong-target name → **fail**.
   (Overlaps SC 4.1.2 — cite there too.)
4. **Informative (a):** compare accName to crop+context.
   - Equivalent purpose conveyed, non-redundant, right level of detail → **pass**.
   - Name is a filename, placeholder, "image", "graphic", the literal `src`, or
     generic ("photo") when the image carries specific meaning (F30) → **fail**.
   - Name present and topical but omits the *information the image adds* (e.g. a
     status icon whose name is the product name, not the status) → **fail**.
5. **Complex (c):** short name PASSES only if a long description is reachable
   (adjacent text, `aria-describedby`, details/summary, linked longdesc) that
   conveys the data. Short name + no long description for data-bearing chart →
   **fail** (equivalent purpose not served) OR **needs_human** if you cannot tell
   whether the adjacent prose already conveys the data.
6. **Image of text (e):** the alt must contain the *same words*. Missing/paraphrased
   → **fail**.
7. If the image's meaning in context is genuinely ambiguous (decorative vs
   informative is a judgment only the author/domain knows), or you cannot read the
   crop clearly → **needs_human**.

**Confidence:** `high` when crop is legible and context text is present; `med` when
you infer role from limited context; `low` → prefer `needs_human`.

## 4. Pass exemplars

- **Contextual, non-redundant.** Crop: a green circle-check next to text
  "Autograder: passed 12/12". `img` accName = "All tests passed". PASS — conveys the
  status the icon adds; not merely "checkmark".
- **Correctly decorative.** Crop: a subtle hero gradient banner. `alt=""`,
  `aria-hidden` absent but empty alt present. Surrounding heading already names the
  page. PASS — decorative, correctly ignored.
- **Complex chart with long description.** Crop: a bar chart of grade distribution.
  `img` accName = "Grade distribution histogram"; `aria-describedby` points to a
  paragraph and a data table serialized in `readingOrder` giving the counts. PASS.
- **Third-party nuance.** A Monaco/editor decorative glyph gutter icon with
  `aria-hidden="true"` and no name — PASS; unconventional but genuinely decorative.

## 5. Fail exemplars

- **Filename/placeholder (F30).** accName = "IMG_2043.png" or "image" on an
  informative avatar-status composite. FAIL, severity 3.
- **Redundant-yet-wrong.** Crop: a red error triangle beside "Submission rejected".
  `img` accName = "triangle" (describes shape, not meaning). FAIL, severity 3 — a
  screen-reader user hears "triangle" and misses the error semantics carried
  visually. Suggested fix: `alt="Error"` or hide it and keep the text.
- **Functional icon named by appearance.** Icon-only button graphic linking to
  profile; accName = "person icon" vs the correct "Your profile". FAIL, severity 4
  (blocks knowing where the control goes). Cross-cite 4.1.2.
- **Data image with no equivalent.** Crop: a chart encoding trend data; accName =
  "chart", no adjacent data, no `describedby`. FAIL, severity 4 — the information is
  unavailable non-visually.
- **Image of text paraphrased.** Banner image reads "Deadline: Friday 5pm";
  `alt="deadline banner"`. FAIL — the actual words are lost.

Third-party-widget caution: a widget rendering an unusual `role="img"` composite is
**not** a failure merely for being unconventional. It fails only if the *equivalent
purpose is not served*. Judge the information, not the implementation style.

## 6. needs_human triggers

- Decorative-vs-informative is a genuine authorial/domain call and context text
  does not disambiguate (e.g. a diagram that *might* be illustrative-only).
- Complex image where you cannot verify whether adjacent prose fully substitutes
  for the visual (needs the long-description text you don't have, or domain expertise).
- Crop is illegible, cropped off, or downscaled below readability.
- Alt text is in a language you cannot evaluate for equivalence, or relies on
  discipline-specific correctness (e.g. a math/CS diagram) you cannot verify.
- Emoji/emoticon/ASCII-art meaning depends on cultural/contextual read.

## 7. Known evidence limits

- ~200-char context window may truncate the true surrounding narrative; the real
  equivalent may live further away (e.g. a caption two paragraphs down). → request
  `expandedTextContext`.
- CSS `background-image` content and `::before` icon fonts may not appear as named
  elements; a meaningful background image could be invisible to the probe entirely.
- The probe cannot confirm a `longdesc`/linked description actually *renders* the
  data correctly — only that a target exists.
- No pixel-level OCR: for images of text the judge relies on human reading of the
  crop; low-res crops defeat this. → request `higherResCrop` / `ocrText`.
- Cannot verify time-based-media or CAPTCHA alternative *forms* from a static shot.

## 8. Severity guidance

- **5** — informative image essential to completing the task conveys nothing
  non-visually (e.g. the only copy of a required instruction is an unlabeled image).
- **4** — functional graphic with wrong/absent purpose name, or data image with no
  equivalent: user cannot know an action's target or read the data.
- **3** — informative image with filename/placeholder/appearance-only name:
  meaning degraded but partially recoverable from context.
- **2** — minor inadequacy: slightly redundant or over-terse alt where context
  mostly covers it.
- **1** — decorative image emitting harmless extra noise; cosmetic.
